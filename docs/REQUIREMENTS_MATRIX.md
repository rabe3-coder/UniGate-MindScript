# مصفوفة مطابقة المتطلبات | Requirements Traceability

المصدر: `assignment.pdf` مع `client.md` الذي غيّر عدد الشعب إلى **2,500** وأضاف Section Swap وأولوية الخريجين. المشروع يستخدم بيانات صغيرة للتجربة. الحالات أدناه تعكس **ما ينفذه الكود حاليًا** ولا تعني قبول الجامعة للسياسات التجريبية.

**المعيار:** ✅ مدعوم بالنموذج واختبار، ◐ مدعوم جزئيًا/محاكاة، ⛔ غير منفذ في هذه النسخة.

## المتطلبات غير الوظيفية

| رمز | المتطلب | الحالة | ملاحظات |
|---|---|---|---|
| N01 | صحة المقاعد واتساق البيانات (Integrity) | ✅ | معاملات SQLite وقيود سعة وتكرار قاعدة البيانات. لا إثبات لحمل إنتاجي موزع |
| N02 | ثبات النتيجة عند إعادة المحاولة (Idempotency) | ✅ | طلبات تسجيل ودفعات تجريبية بمفاتيح فريدة |
| N03 | عدالة مستقلة عن تحديث الصفحة وسرعة الإنترنت | ◐ | قائمة الانتظار متسلسلة مع سياسة أولوية؛ لا غرفة انتظار موزعة فعلية |
| N04 | استجابة 12,000 مستخدم في 5 دقائق و4 خوادم | ⛔ | لم يجر اختبار حمل فعلي أو نشر Nginx/PM2 بأربع عقد |
| N05 | القراءة تبقى متاحة عند إيقاف التسجيل للطوارئ | ✅ | `registration_enabled=false` يمنع كتابات حساسة ويحافظ على الكتالوج والقراءات |
| N06 | التفسير وسجل التغييرات والرفض | ◐ | `audit` يغطي أغلب العمليات المهمة، لكن لا يغطي جميع الأخطاء الأمنية/الشبكية |
| N07 | الأمن والصلاحيات | ◐ | كلمات مرور PBKDF2، cookies HttpOnly SameSite، انتهاء جلسة خادم، فحص Origin وأدوار؛ لا TLS أو MFA أو تدقيق أمني إنتاجي |
| N08 | قابلية التعديل والصيانة | ✅ | فصل الطبقات والاختبارات والترقيات الإضافية؛ بعض SQL ما زال في Application |
| N09 | قابلية نشر متعدد العقد وتحمل الأعطال | ⛔ | SQLite محلية وخادم واحد، لا خدمة Redis/Queue ولا Failover أو مراقبة |
| N10 | تعدد اللغات والمظهر المتجاوب | ✅ | ملفات واجهة مقسمة، RTL/LTR، ألوان داكن/فاتح |
| N11 | عدم فقد بيانات النسخة الحالية عند الترقية | ✅ | `init_db()` إضافي ولا يعيد seed إن كان يوجد مستخدمون؛ اختبارات الهجرة |

## ما يلزم لقبول إنتاجي

1. اعتماد سياسات الجامعة المكتوبة: السلة الجزئية، الحد الأدنى، مهلة قبول مقعد الانتظار، قيمة حماية غير الخريج، صفة الخريج والتفوق، وإلغاء التسجيل بعد تعديل العلامة.
2. تكامل بوابة الدفع وعمليات الاستعلام والتسوية والاسترداد فعليًا، والدرجات والجداول والخطط.
3. مخطط بيانات للخطط/الاختيارات/اللقاءات المتعددة والقاعة والمدرس، وصلاحيات القبول اليدوي بشؤون الطلاب.
4. تحويل من SQLite إلى قاعدة خادمية مناسبة، واختبارات حمل/اختراق وحماية ومراقبة ونسخ احتياطي واستعادة.
5. غرفة انتظار عادلة موزعة مع منع تكرار تذاكر الطالب، Rate Limiting على مستوى البوابة، والتعامل مع الخادم المعطل وإعادة التشغيل، واختبارات تعافٍ.
